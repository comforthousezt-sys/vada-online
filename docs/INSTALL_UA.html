Збірка 0.2.0-alpha.1 · 3 жовтня 2026 року

Готовий сайт встановлюємо на HOSTiQ. Babylon.js уже входить у файли сайту та малює 3D-мапу в браузері. Render запускає онлайн-сервер кімнат; для постійного збереження підключаємо PostgreSQL, наприклад Supabase.

Частина Де працює Що завантажуємо
Сайт, інтерфейс і Babylon.js HOSTiQ → браузер Вміст VADA_HOSTIQ_0.2_ALPHA.zip
Правила онлайн-партії, боти, чат, обмін Render Web Service Репозиторій із VADA_SOURCE_0.2_ALPHA.zip
Приватний стан кімнат Supabase PostgreSQL server/schema.sql; рядок підключення зберігаємо на Render

vada.example.com і your-vada-server.onrender.com нижче — приклади. Замініть їх своїми адресами. Конкретний домен і віддалені сервіси в цій збірці ще не налаштовано.

1. Завантажте сайт на HOSTiQ

  1. Збережіть резервну копію поточного сайту, якщо використовуватимете його папку. Для альфи зручно створити окремий піддомен, наприклад vada.ВАШ-ДОМЕН, або папку /vada/.
  2. Увійдіть у cPanel через особистий кабінет HOSTiQ. У розділі Domains подивіться Document Root потрібного домену. Для головного домену це часто public_html, але орієнтуйтеся на свою панель.
  3. Відкрийте File Manager, перейдіть саме в цю папку й завантажте VADA_HOSTIQ_0.2_ALPHA.zip через Upload.
  4. Виділіть архів → Extract у цій папці. Після розпакування поруч мають лежати index.html, config.js, favicon.svg, .htaccess і папка assets/. Додаткова папка dist/ не потрібна. Увімкніть показ прихованих файлів, щоб перевірити .htaccess.
  5. Видаліть лише завантажений ZIP із публічної папки після розпакування. Код сервера й .env туди не завантажуємо.
  6. Увімкніть SSL для цього домену засобами HOSTiQ / cPanel і відкрийте сайт через HTTPS. Переконайтеся, що показується VADA та запускається тренування з ботами.

На цьому етапі повна локальна партія вже працює. Онлайн відкриється після кроків 3–5. Якщо сайт розміщено в /vada/, відкривайте адресу з завершальним /: https://ВАШ-ДОМЕН/vada/.

Сайт не потребує Node.js, npm чи процесу Babylon.js на HOSTiQ. PHP і MySQL для цієї збірки не використовуються.

2. Як підключено Babylon.js

Підключення вже виконано в проєкті:

import { Engine } from '@babylonjs/core/Engines/engine.js';
import { Scene } from '@babylonjs/core/scene.js';
import { ArcRotateCamera } from '@babylonjs/core/Cameras/arcRotateCamera.js';

Сцена знаходиться у web/src/components/Board.tsx: парламент, 20 місць маршруту, 12 будівель, п’ять фігур NUMBRA, світло, тіні та камера. Використовується зафіксований пакет @babylonjs/core 9.29.0. CDN і сторонній API-ключ не потрібні: Vite складає залежності в папку assets/.

Якщо змінюватимете код на своєму комп’ютері:

npm ci
npm run build:web

Завантажте на HOSTiQ вміст нової dist/ і знову задайте адресу API у config.js, якщо збірка містить порожнє значення. Оновлюйте index.html і всю папку assets/ разом: імена JS-файлів змінюються після збірки.

Для перевірки 3D відкрийте головну сторінку, потягніть мапу та змініть масштаб колесом миші. У партії є кнопка Плоска карта й доступний клавіатурою список усіх місць. Якщо WebGL недоступний, сайт автоматично показує спрощену мапу. Фінальні художні моделі та озвучення залишаються окремим наступним етапом.

3. Підготуйте базу Supabase

  1. У своєму Supabase-проєкті відкрийте SQL Editor.
  2. Скопіюйте весь файл server/schema.sql із архіву вихідного коду й виконайте його. Він створює vada_private.rooms, вмикає RLS і закриває доступ для public, anon та authenticated.
  3. Не додавайте vada_private до Exposed schemas у Data API. Повний стан містить чужі приховані карти й цілі; браузеру потрібна лише персональна проєкція від Render.
  4. Натисніть Connect і скопіюйте рядок підключення Session pooler, порт 5432. Для тривалого серверного з’єднання через IPv4 Supabase рекомендує саме session mode. Ім’я користувача та хост копіюйте з панелі, не складайте вручну.
  5. Вставте пароль бази у рядок підключення. Якщо пароль містить @, :, /, #, % чи інші спеціальні символи, їх потрібно URL-кодувати. Рядок із паролем зберігаємо лише у змінній DATABASE_URL на Render.

У цій альфі сервер використовує адміністративний рядок PostgreSQL із Connect для приватної таблиці. Для публічного запуску заплановано окрему роль БД з доступом лише до схеми кімнат. Ключі Supabase anon / service_role для встановлення цієї збірки не потрібні; Supabase Auth ще не підключено.

TLS: сервер перевіряє сертифікат бази. Якщо під час запуску є помилка self signed certificate / unable to verify, завантажте CA-сертифікат бази з Database Settings у Supabase та передайте його в DATABASE_SSL_CA_BASE64 на Render.

Linux / macOS:

base64 < prod-supabase.cer | tr -d '\n'

Windows PowerShell:

[Convert]::ToBase64String([IO.File]::ReadAllBytes("prod-supabase.cer"))

Скопіюйте результат як значення змінної. Якщо TLS працює із системним сховищем довіри, додатковий CA можна не задавати. Код навмисно не вимикає перевірку TLS.

4. Підключіть сервер до Render

  1. Розпакуйте VADA_SOURCE_0.2_ALPHA.zip на комп’ютері.
  2. Створіть репозиторій GitHub і завантажте в нього розпаковані файли. У корені репозиторію мають бути package.json, package-lock.json, render.yaml, server/, shared/, web/, tests/. Якщо додаєте папку-обгортку, її назву потрібно окремо задати в Render Root Directory.
  3. У Render натисніть New → Web Service, підключіть GitHub і виберіть цей репозиторій.
  4. Заповніть параметри:
Поле Значення
Name vada-rooms або власна назва
Language / Runtime Node
Region Frankfurt або регіон поруч із вашою базою
Branch Ваша основна гілка, зазвичай main
Root Directory Порожньо, якщо package.json у корені
Build Command npm ci --include=dev && npm run build:server
Start Command npm start
Health Check Path /healthz
Instance Type Free для початкової альфи
  1. Додайте змінні в Environment:
Змінна Значення
NODE_VERSION 24.19.0
ALLOWED_ORIGINS Реальний origin сайту, наприклад https://vada.example.com
DATABASE_URL Приватний PostgreSQL Session pooler URI з кроку 3
DATABASE_SSL_CA_BASE64 CA у base64, якщо потрібний для TLS
ALLOW_EPHEMERAL false

ALLOWED_ORIGINS містить протокол і домен, без завершального / та без шляху. Для сайту https://example.com/vada/ правильне значення — https://example.com. Якщо доступні і www, і домен без www, запишіть обидва origin через кому або налаштуйте один канонічний домен. Секретний DATABASE_URL не додавайте в Git чи config.js.

Змінну PORT вручну задавати не потрібно: сервер використовує Render PORT і слухає 0.0.0.0. Таймери можна залишити типовими або задати TURN_SECONDS=30, PROPOSAL_SECONDS=30, DEBATE_SECONDS=120, VOTE_SECONDS=30; допустимі цілі значення 5–600. Реакція триває 20 секунд.

  1. Натисніть Create Web Service і дочекайтеся статусу Live. Скопіюйте фактичну адресу сервісу, наприклад https://your-vada-server.onrender.com.
  2. Відкрийте https://АДРЕСА-RENDER/healthz. Очікуваний результат:
{"ok":true,"rulesVersion":"0.2.0-alpha.1","persistence":"postgres"}

Якщо бачите ephemeral-demo, це демонстраційний режим без постійного збереження. Для штатної установки потрібен postgres.

Альтернатива: у репозиторії є готовий render.yaml. Можна створити New → Blueprint, вибрати репозиторій та ввести потрібні змінні під час створення. Розгортайте один екземпляр; горизонтальне масштабування в цій альфі не реалізовано.

5. З’єднайте HOSTiQ із Render

У cPanel File Manager відкрийте config.js у папці сайту → Edit. Замініть порожній рядок на фактичну адресу Render:

window.VADA_CONFIG = {
  apiBase: 'https://your-vada-server.onrender.com'
};

Збережіть і оновіть сайт із очищенням кешу. Адреса має бути https, без /ws, /api чи порту. Браузер сам використовує HTTP API та захищене WebSocket-з’єднання wss до /ws. Додавати JS-файл Render на сторінку не потрібно.

6. Перевірте встановлення

  1. Запустіть тренування, купіть актив, оновіть сторінку й натисніть Продовжити тренування. Прогрес має відновитися.
  2. Відкрийте Грати з друзями, задайте ім’я й створіть кімнату.
  3. Скопіюйте запрошення. Відкрийте його в іншому браузері / приватному вікні, натисніть Грати з друзями → Увійти за кодом, введіть код і виберіть іншу NUMBRA.
  4. Власник кімнати додає бота або третього гравця й натискає Почати партію.
  5. Перевірте хід, повідомлення в чаті та обмін монетами. Зміни мають бути видимі обом сторонам; карти й особисті цілі кожен бачить лише свої.
  6. Оновіть початкову вкладку й натисніть Повернутись до кімнати. Має відновитися те саме місце. Сам код кімнати не дає доступу до втраченого приватного місця.
  7. Поза активною партією перезапустіть сервіс через Render і перевірте повернення до кімнати. При persistence=postgres кімната та підтверджені дії мають зберегтися.

Зберігайте початкову вкладку: приватний токен повернення живе в sessionStorage цієї вкладки. Облікові записи й відновлення через email з’являться на наступному етапі. Кімнати видаляються після 24 годин без збережених змін. Онлайн-час не зупиняється при втраті зв’язку; після відновлення прострочена дія виконується за правилами таймера.

7. Типові проблеми

Симптом Що перевірити
«Онлайн поки недоступний» config.js: непорожній правильний apiBase; очистіть кеш
Біла сторінка, JS 404 index.html і assets/ поруч; розпакуйте весь frontend ZIP; перевірте завершальний / для підпапки
API 403 / WebSocket не підключається ALLOWED_ORIGINS точно збігається з origin сторінки; www також має значення
Mixed content І сайт HOSTiQ, і адреса Render мають починатися з https://
Render не знаходить package.json Виправте структуру GitHub або Root Directory
Сервер не запускається / healthz недоступний DATABASE_URL, пароль, schema.sql, підключення Session pooler і TLS CA; перегляньте Render Logs
Кімната зникла після перезапуску persistence має бути postgres; ALLOW_EPHEMERAL=false; база доступна; минуло менш ніж 24 год
«NUMBRA уже обрали» Виберіть іншу істоту; в кімнаті архетипи унікальні
«Місце гравця не підтверджено» Поверніться в початкову вкладку; код запрошення не є приватним токеном
«Стан змінився» Подивіться оновлену партію й повторіть вибір; дія ще не була підтверджена
Карта спрощена Увімкніть WebGL / апаратне прискорення або користуйтеся плоскою картою
HTTP 500 після .htaccess Якщо ваш тариф забороняє Options, приберіть лише рядок Options -Indexes і повторіть; уточніть дозволи в підтримки HOSTiQ

На Render Free після 15 хвилин без вхідного трафіку сервіс засинає; пробудження займає приблизно хвилину. Локальні файли втрачаються при перезапуску / redeploy, тому збереження винесене у PostgreSQL. Безкоштовна база Render Postgres має обмеження 30 днів; ця інструкція використовує окремий Supabase-проєкт. Для публічної гри без холодного старту вибір платного тарифу й перевірку навантаження робимо окремо. Поточні ліміти та вартість перевіряйте в панелях провайдерів.

8. Оновлення і відкат

Збережіть копію встановлених index.html, config.js, assets/ і .htaccess. Перед оновленням заверште поточні партії: зміна версії правил потребуватиме окремої міграції старих кімнат. Спочатку оновіть сервер з відповідної версії вихідного коду й перевірте /healthz, потім завантажте frontend тієї самої версії. Адресу в config.js збережіть.

Для відкату поверніть попередній серверний deploy і відповідний frontend. Не використовуйте вихідний архів як архів сайту. Архів VADA_HOSTIQ містить лише файли, які можна віддавати браузеру.

Vercel у цій схемі не потрібний. PostHog, Supabase Auth, профілі, колекція, постійні образи, QR фізичних фігурок, гібриди й оплати ще не підключені. Їхній порядок описано в docs/RELEASE_UA.md; обіцянки інтерфейсу позначені як заплановані.
